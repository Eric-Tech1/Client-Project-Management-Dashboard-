# Brandville Client Project Management Dashboard

Full-stack technical assessment project built with Laravel 12, React + Vite, and MySQL.

## Features
- Dashboard counts for total, Not Started, In Progress, and Completed projects
- Create, view, edit, and delete projects
- Search by project or client name; filter by status
- Server-side validation and clear API errors
- Persistent MySQL storage through Laravel migrations
- Responsive interface
- Laravel feature tests

## Stack
- Frontend: React, Vite, Lucide React
- Backend: Laravel 12 / PHP 8.2+
- Database: MySQL 8+
- API: REST JSON

## Why these technologies
- **Laravel (PHP):** built-in validation, Eloquent ORM, migrations and routing keep the API short, safe and easy to read.
- **React + Vite:** fast component-based UI with instant search/filter updates and a quick build.
- **MySQL:** a reliable relational database; data survives restarts and the schema is versioned through migrations.
- **REST JSON API:** a clear contract between the frontend and backend, so each can be deployed separately.

## Required environment variables
**Backend (`backend/.env`)**

| Variable | Purpose |
|---|---|
| `APP_KEY` | Generated by `php artisan key:generate` |
| `APP_ENV`, `APP_DEBUG`, `APP_URL` | Environment settings (`production` / `false` when deployed) |
| `DB_CONNECTION`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD` | MySQL connection |
| `FRONTEND_URL` (or `CORS_ALLOWED_ORIGINS`) | Frontend origin allowed by CORS |

**Frontend (`frontend/.env`)**

| Variable | Purpose |
|---|---|
| `VITE_API_BASE_URL` | Base URL of the API, e.g. `http://127.0.0.1:8000/api` |

No secrets are committed; `.env` files are git-ignored and only `.env.example` files are included.

## Database structure
One table, `projects` (migration: `backend/database/migrations/2026_10_27_000001_create_projects_table.php`).

| Column | Type | Notes |
|---|---|---|
| `id` | bigint, PK, auto-increment | |
| `name` | varchar(255) | required |
| `client_name` | varchar(255) | required, indexed for search |
| `description` | text | optional |
| `start_date` | date | required |
| `due_date` | date | required, must be on/after `start_date` (validated) |
| `status` | varchar(30) | `not_started` (default), `in_progress`, `completed`; indexed for filtering |
| `created_at`, `updated_at` | timestamps | |

Dashboard figures are computed live with `COUNT` queries on `status`, so they always match the stored data.

## Local setup
### Backend
1. Install PHP 8.2+, Composer, and MySQL.
2. `cd backend`
3. Copy `.env.example` to `.env` (on Windows: `Copy-Item .env.example .env`)
4. Create a MySQL database named `brandville_dashboard` and set DB values in `.env`.
5. Run:
   ```bash
   composer install
   php artisan key:generate
   php artisan migrate
   php artisan serve
   ```
   API base URL: `http://127.0.0.1:8000/api`

### Frontend
1. In a second terminal: `cd frontend`
2. `npm install`
3. Copy `.env.example` to `.env` and set `VITE_API_BASE_URL=http://127.0.0.1:8000/api`
4. `npm run dev -- --host 0.0.0.0`

Open the URL Vite prints (usually `http://localhost:5173`).

## API endpoints
- `GET /api/projects?search=&status=`
- `POST /api/projects`
- `GET /api/projects/{id}`
- `PUT /api/projects/{id}`
- `DELETE /api/projects/{id}`
- `GET /api/dashboard`

Allowed statuses: `not_started`, `in_progress`, `completed`. `due_date` must be on or after `start_date`.

## Tests
From `backend/` run:
```bash
php artisan test
```
Tests cover listing, create/show/update/delete, search/status filters, validation, and dashboard counts. Run them in a configured PHP/Composer environment; this ZIP does not include vendor dependencies.

## Deployment notes
The React frontend can be deployed to a static host such as Netlify by connecting the `frontend` folder/repository and setting `VITE_API_BASE_URL` to the deployed Laravel API URL. Build command: `npm run build`; publish directory: `dist`.

The Laravel backend needs a PHP-capable host and a reachable MySQL database. Set production environment variables (`APP_KEY`, `APP_ENV=production`, `APP_DEBUG=false`, `APP_URL`, `DB_CONNECTION=mysql`, `DB_HOST`, `DB_PORT`, `DB_DATABASE`, `DB_USERNAME`, `DB_PASSWORD`, `FRONTEND_URL`). Run `php artisan migrate --force` after configuring the database. Do not commit `.env` or credentials.

Free hosting plans and MySQL availability change; verify the current provider terms before choosing. A deployed frontend alone is not a complete deployed application until its API and database are reachable.
